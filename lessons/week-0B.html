Core · HTTP and httpx

1. HTTP in one picture

Every API call is a request (a method like GET or POST, a URL, headers, and sometimes a body) followed by a response (a status code, headers, and a body, usually JSON). LLM APIs, CRMs and ticketing systems all work this way.

StatusMeaningWhat your code should do
200–299SuccessRead the body
400Bad request (your input is wrong)Don't retry; fix the input and report it
401 / 403Not authenticated / not allowedDon't retry; check the key or permissions
404Not foundOften a valid answer: "this doesn't exist"
429Too many requests (rate limit)Wait, then retry (respect Retry-After)
500–599Server errorRetry a few times with growing waits

2. Calling an API with httpx

3. Failing well: raise_for_status, timeouts, retries

resp = client.get(url)
if resp.status_code == 404:
    return None                     # a real answer: no such ZIP
resp.raise_for_status()             # raises httpx.HTTPStatusError for any other 4xx/5xx

Networks fail. Retry only what can succeed on a second try: timeouts, connection errors (httpx.TransportError) and 5xx responses. Wait longer each time (0.5s, 1s, 2s…), which is called exponential backoff. Never retry a 400: it will fail the same way.

Why this matters for agentsLLM APIs return 429 and 5xx errors under load. Every agent you build needs exactly this retry logic. In Week 6 you'll also design tools that report errors this clearly back to the model.
Exercise 1

A ZIP lookup client with retries

~50 min

In code/week-0B/ex1-zip/zipclient.py, write lookup_zip(client, zip_code, retries=3):

  1. GET https://api.zippopotam.us/us/{zip} with a 5-second timeout.
  2. Return None for 404, and {"city": ..., "state": ...} for a hit.
  3. Retry transport errors and 5xx responses up to retries times with exponential backoff, logging a WARNING each time; re-raise after the last attempt. Never retry other 4xx errors.
  4. Try it on 75024, 02108 and 00000.

Check: 75024 → {"city": "Plano", "state": "TX"}; 00000 → None. On Day 3 you'll test it without the internet.

Pass the client in rather than creating it inside. That makes the function reusable (one connection pool) and testable (you can pass a fake client later). Wrap the request in a for attempt in range(...) loop; try the call, and in except decide whether this error is worth retrying.
for attempt 1..retries: try: resp = get; if 404 → None; raise_for_status; return parsed → except TransportError or HTTPStatusError: retryable = transport error or status ≥ 500; if last attempt or not retryable → raise; log warning; sleep(0.5 × 2^(attempt-1))
except (httpx.TransportError, httpx.HTTPStatusError) as e:
    is_server_error = isinstance(e, httpx.HTTPStatusError) and e.response.status_code >= 500
    if attempt == retries or not (isinstance(e, httpx.TransportError) or is_server_error):
        raise
import logging
import time

import httpx

logger = logging.getLogger(__name__)
BASE_URL = "https://api.zippopotam.us/us/"


def lookup_zip(client: httpx.Client, zip_code: str, retries: int = 3) -> dict | None:
    """Return {"city", "state"} for a US ZIP, None if the ZIP doesn't exist.
    Retries network errors and 5xx responses; raises after the last attempt."""
    for attempt in range(1, retries + 1):
        try:
            resp = client.get(BASE_URL + zip_code, timeout=5.0)
            if resp.status_code == 404:
                return None
            resp.raise_for_status()
            place = resp.json()["places"][0]
            return {"city": place["place name"], "state": place["state abbreviation"]}
        except (httpx.TransportError, httpx.HTTPStatusError) as e:
            is_server_error = isinstance(e, httpx.HTTPStatusError) and e.response.status_code >= 500
            if attempt == retries or not (isinstance(e, httpx.TransportError) or is_server_error):
                raise
            logger.warning("Attempt %s for %s failed (%s); retrying", attempt, zip_code, e)
            time.sleep(0.5 * 2 ** (attempt - 1))
    return None


if __name__ == "__main__":
    with httpx.Client() as client:
        for z in ["75024", "02108", "00000"]:
            print(z, lookup_zip(client, z))

function parseCreditScore(raw: string): number {
  if (raw.trim() === "") throw new Error("credit_score is missing");
  const score = Number(raw);
  if (!Number.isInteger(score)) throw new Error(`not a whole number: ${raw}`);
  if (score < 300 || score > 850) throw new Error(`credit_score ${score} is outside 300-850`);
  return score;
}

Core · Pydantic

Last week you wrote about 60 lines of validation by hand. Pydantic lets you declare the shape and rules of your data as a class, and it does the converting, checking and error reporting for you. It's used everywhere in the agent world: FastAPI, the OpenAI and Claude SDKs, LangChain, and structured LLM output (Week 1).

(.venv) $ pip install pydantic
from datetime import date
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, ValidationError, field_validator


class Lead(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)   # trim every string

    lead_id: str = Field(min_length=1)
    credit_score: int = Field(ge=300, le=850)       # "742" is converted to 742
    loan_amount: float = Field(gt=0, le=5_000_000)
    loan_type: Literal["purchase", "refinance"]     # only these two values
    created_at: date                                # "2026-09-31" is rejected
    zip: str = Field(pattern=r"^\d{5}$")            # stays a string: keeps "02108"

    @field_validator("loan_type", mode="before")    # runs BEFORE type checking
    @classmethod
    def lower_loan_type(cls, v):
        return v.strip().lower() if isinstance(v, str) else v


try:
    lead = Lead(lead_id="L-1", credit_score="905", loan_amount="385000",
                loan_type="Purchase", created_at="2026-09-01", zip="75024")
except ValidationError as e:
    for err in e.errors():
        print(err["loc"][0], "→", err["msg"])      # credit_score → Input should be less than or equal to 850
  • Constraints go in Field(...): ge/le (≥/≤), gt, min_length, pattern.
  • Custom rules go in a @field_validator that raises ValueError. Pydantic collects all errors, not just the first.
  • e.errors() gives a list of dicts with loc (which field) and msg, ready for your report.
  • lead.model_dump(mode="json") turns the model back into JSON-ready data (dates become strings).
  • Some rules need context from other rows, like duplicate IDs. Those stay outside the model.

Enterprise · TypeScript II: interfaces and unions

An interface describes the shape of an object (like a Pydantic model without the runtime checks). A union of literal types restricts a value to a fixed set, like Python's Literal. Add these to lead.ts and run it with node lead.ts:

type LoanType = "purchase" | "refinance";

interface Lead {
  leadId: string;
  creditScore: number;
  loanType: LoanType;
  zip: string;
}

function parseLoanType(raw: string): LoanType {
  const v = raw.trim().toLowerCase();
  if (v === "purchase" || v === "refinance") return v;   // TypeScript narrows v to LoanType here
  throw new Error(`unknown loan type: ${raw}`);
}

const lead: Lead = { leadId: "L-1001", creditScore: parseCreditScore("742"),
                     loanType: parseLoanType("Purchase"), zip: "75024" };
console.log(lead);
Important differenceTypeScript types are checked while you write code and then erased. At run time nothing validates the data. If a value comes from an API, you still need runtime checks, which is why functions like parseLoanType exist.

Testing code that calls an API, without the internet

Tests must be fast and never depend on someone else's server. httpx lets you swap the network for a function that returns fake responses:

import httpx
from zipclient import lookup_zip


def fake_api(request: httpx.Request) -> httpx.Response:
    if request.url.path.endswith("/75024"):
        return httpx.Response(200, json={"places": [{"place name": "Plano", "state abbreviation": "TX"}]})
    return httpx.Response(404, json={})


def test_lookup_zip_found_and_missing():
    client = httpx.Client(transport=httpx.MockTransport(fake_api))
    assert lookup_zip(client, "75024") == {"city": "Plano", "state": "TX"}
    assert lookup_zip(client, "00000") is None

This is why Exercise 1 took the client as a parameter. For files, pytest gives each test a fresh temporary folder: add a tmp_path argument and write there.

        calls["n"] += 1

Core · async / await

Looking up 1,000 ZIP codes one at a time spends almost all its time waiting on the network. async lets one program wait on many requests at once. Agents use this to call several tools or models in parallel.

import asyncio
import httpx


async def lookup_one(client: httpx.AsyncClient, sem: asyncio.Semaphore, zip_code: str):
    async with sem:                                   # at most N requests in flight
        resp = await client.get(f"https://api.zippopotam.us/us/{zip_code}", timeout=5.0)
        ...


async def lookup_many(zips: list[str], limit: int = 5) -> dict:
    sem = asyncio.Semaphore(limit)                    # be polite: don't flood the API
    async with httpx.AsyncClient() as client:
        results = await asyncio.gather(*(lookup_one(client, sem, z) for z in set(zips)))
    return dict(results)


print(asyncio.run(lookup_many(["75024", "02108", "00000"])))
  • async def makes a function a coroutine; await pauses it while it waits, so other coroutines can run.
  • asyncio.gather runs many coroutines at once and returns their results in order.
  • A Semaphore caps how many run at the same time, which keeps you under the API's rate limit.
  • asyncio.run(...) starts everything from normal (non-async) code.

import asyncio

import httpx

BASE_URL = "https://api.zippopotam.us/us/"


async def lookup_one(client: httpx.AsyncClient, sem: asyncio.Semaphore, zip_code: str) -> tuple[str, dict | None]:
    async with sem:
        resp = await client.get(BASE_URL + zip_code, timeout=5.0)

        resp.raise_for_status()

    async with httpx.AsyncClient(transport=transport) as client:
        results = await asyncio.gather(*(lookup_one(client, sem, z) for z in set(zips)))
    return dict(results)

Enterprise · TypeScript III: async and fetch

TypeScript's async/await works almost exactly like Python's. fetch is built into Node. Write zip.ts and run it with node zip.ts:

interface Place { "place name": string; "state abbreviation": string }
interface ZipResponse { places: Place[] }

async function lookupZip(zip: string): Promise<{ city: string; state: string } | null> {
  const resp = await fetch(`https://api.zippopotam.us/us/${zip}`);
  if (resp.status === 404) return null;
  if (!resp.ok) throw new Error(`HTTP ${resp.status}`);
  const data = (await resp.json()) as ZipResponse;     // "as" is a promise to the checker, not a runtime check
  const p = data.places[0];
  return { city: p["place name"], state: p["state abbreviation"] };
}

const results = await Promise.all(["75024", "00000"].map(lookupZip));   // like asyncio.gather
console.log(results);

Core · SQLite from Python

SQLite is a full SQL database in a single file, built into Python. The SQL you learn here works (with small differences) on Postgres, Snowflake and the warehouses your customers use.

import sqlite3

conn = sqlite3.connect("out/leads.db")            # creates the file if needed; ":memory:" for tests
conn.execute("""
CREATE TABLE IF NOT EXISTS leads (
    lead_id        TEXT PRIMARY KEY,
    credit_score   INTEGER NOT NULL,
    property_state TEXT NOT NULL
)""")

rows = [{"lead_id": "L-1001", "credit_score": 742, "property_state": "TX"}]
conn.executemany(
    "INSERT OR REPLACE INTO leads VALUES (:lead_id, :credit_score, :property_state)",   # named parameters
    rows,
)
conn.commit()                                       # nothing is saved until you commit

for state, n in conn.execute("SELECT property_state, COUNT(*) FROM leads GROUP BY property_state"):
    print(state, n)
Never build SQL with f-stringsf"SELECT * FROM leads WHERE email = '{email}'" lets a crafted input like ' OR '1'='1 rewrite your query. That's SQL injection, one of the most exploited bugs in history. Always pass values as parameters (? or :name) and let the driver handle them. Agents that generate SQL (Week 19) make this even more important.

Core · Branches and pull requests

On a team, and at a customer, you never push straight to main. You work on a branch, open a pull request (PR), someone reviews the diff, then it's merged. You'll do this for every project from now on, even alone: reviewing your own diff catches mistakes.

$ git switch -c add-sqlite-store          # new branch
# … edit, test, commit …
$ git push -u origin add-sqlite-store
$ gh pr create --fill                      # open a PR from your commits
$ gh pr diff                               # review your own changes line by line
$ gh pr merge --squash --delete-branch     # merge when it's right
$ git switch main && git pull

A good PR description says what changed, why, and how you tested it.

Named parameters (:lead_id) read values straight from each dict, so executemany(sql, list_of_dicts) inserts them all. ROUND(AVG(credit_score), 1) does the average in SQL. Order with ORDER BY COUNT(*) DESC, property_state.
import sqlite3

SCHEMA = """
CREATE TABLE IF NOT EXISTS leads (
    lead_id        TEXT PRIMARY KEY,
    full_name      TEXT NOT NULL,
    email          TEXT NOT NULL,
    loan_amount    REAL NOT NULL,
    credit_score   INTEGER NOT NULL,
    property_state TEXT NOT NULL,
    city           TEXT
)
"""


def save_leads(conn: sqlite3.Connection, leads: list[dict]) -> None:
    conn.execute(SCHEMA)
    conn.executemany(
        "INSERT OR REPLACE INTO leads VALUES (:lead_id, :full_name, :email, :loan_amount, "
        ":credit_score, :property_state, :city)",
        leads,
    )
    conn.commit()


def leads_per_state(conn: sqlite3.Connection) -> list[tuple[str, int, float]]:
    return conn.execute(
        "SELECT property_state, COUNT(*), ROUND(AVG(credit_score), 1) FROM leads "
        "GROUP BY property_state ORDER BY COUNT(*) DESC, property_state"
    ).fetchall()

import pandas as pd

df = pd.read_csv("leads_v2.csv", dtype={"zip": str, "lead_id": str})
df["credit_score"] = pd.to_numeric(df["credit_score"], errors="coerce")   # bad → NaN
df["loan_amount"] = pd.to_numeric(df["loan_amount"], errors="coerce")
clean = df.dropna(subset=["credit_score", "loan_amount"]).drop_duplicates(subset="lead_id")
summary = (clean[clean["loan_amount"] > 0]
           .groupby("property_state")
           .agg(leads=("lead_id", "count"), avg_score=("credit_score", "mean"))
           .sort_values("leads", ascending=False))
print(summary.round(1).head(3))
