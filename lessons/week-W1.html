Core · Agents, workflows, and tools

A short talk version: don't build agents for everything, keep them simple, think like your agent.

Read

Read the overview and the first full example. You'll implement exactly this today.

Summary

  • Workflow: your code decides the steps; the model fills in each one (for example extract, then classify, then draft). Predictable, cheap, easy to test.
  • Agent: the model decides the next step from what it has seen so far, in a loop, until it's done. Flexible, but less predictable and more expensive.
  • Start with the simplest thing that works. Use an agent only when the steps can't be known ahead of time. Many "agents" in production are workflows with one smart step.
  • The agent equation: instructions + tools + memory, run by a model, inside a loop you control (with a step limit, logging and cost tracking).
  • Function calling: you describe tools as JSON schemas. The model never runs anything. It replies with a function_call (a name and JSON arguments); your code runs the function and sends back a function_call_output with the same call_id. Then the model continues.
  • Why tools matter: they give the model fresh data (databases, APIs) and exact computation (math, dates), which is exactly where Week 0C showed models are weakest.

Core · Tools a model can use well, and output your code can trust

Read
Anthropic: Writing effective tools for agents ↗

How to name, describe and shape tools, and what to return from them.

Read
OpenAI: Structured model outputs ↗

Read the Pydantic example and the section on refusals.

Summary

  • Strict mode ("strict": true) makes arguments always match your schema. Its rules: additionalProperties: false on every object, and every property listed in required. An optional field is written as a type that allows null.
  • Descriptions are prompts. Name tools and parameters clearly, give units and examples ("annual rate in percent, e.g. 6.5"), and use enum for fixed choices. The test: could a new colleague use the tool from its description alone?
  • Keep the tool set small (OpenAI suggests fewer than 20 at a time), and merge tools that are always called together.
  • Return errors as data ({"error": "no lead with id L-9999"}) instead of crashing, so the model can recover or explain.
  • Structured output: client.responses.parse(..., text_format=MyModel) makes the model reply in your Pydantic model's shape; read it from response.output_parsed. It's None if the model refused, so check before using it.
  • Tools vs structured output: use tools when the model needs to act or fetch; use structured output when you need its final answer in a shape your code can store.
  • The schema checks shape, not business rules. Add Pydantic validators for rules like "a hot lead must score 8–10".

In Pydantic, str | None with no default becomes "required but nullable" in the schema, which is exactly what strict mode wants. Literal[...] | None gives an enum that also allows null.
from typing import Literal

from openai import OpenAI
from pydantic import BaseModel


class LeadIntake(BaseModel):
    full_name: str | None
    email: str | None
    loan_amount: float | None
    loan_type: Literal["purchase", "refinance"] | None
    property_state: str | None
    credit_score: int | None
    missing_fields: list[str]


INSTRUCTIONS = ("Extract the mortgage lead from the broker's email. Use null for anything not stated; "
                "never guess. property_state is a two-letter US code. List the null fields in missing_fields.")


def extract(client: OpenAI, email_text: str) -> LeadIntake:
    response = client.responses.parse(model="gpt-6-luna", instructions=INSTRUCTIONS,
                                      input=email_text, text_format=LeadIntake)
    if response.output_parsed is None:
        raise ValueError("no structured output (the model may have refused)")
    return response.output_parsed

Core · Turning one tool call into an agent

The loop in six lines

repeat up to max_steps:
    response = model(conversation, tools)
    conversation += response.output            # includes reasoning items: send them back
    calls = function calls in response.output
    if no calls: return response.output_text   # the model is done
    for each call: run it, append its function_call_output
  • The stopping condition is "the model asked for no tools", never a keyword in the text.
  • A step limit is your safety net against loops that never end (and bills that never stop).
  • Parallel calls: one response can contain several function calls. Run them all, then call the model once.
  • A dispatcher maps tool names to Python functions, rejects unknown names, and turns exceptions into {"error": ...} results.
  • A trace (each tool, its arguments and its result) is how you debug an agent. Print it now; next week you'll store it.
  • Track tokens and cost across every call in the loop: an agent makes several calls per task.
  • Short-term memory is simply the conversation list. Keep it between questions and the agent can answer follow-ups.

def run(self, name: str, arguments: str) -> str:
    if name not in {t["name"] for t in TOOLS}:
        return json.dumps({"error": f"unknown tool {name}"})
    try:
        return json.dumps(getattr(self, name)(**json.loads(arguments)))
    except (LookupError, ValueError, TypeError) as e:
        return json.dumps({"error": str(e)})
import json
import sqlite3

from openai import OpenAI


def tool(name, description, properties):
    return {"type": "function", "name": name, "description": description, "strict": True,
            "parameters": {"type": "object", "properties": properties,
                           "required": list(properties), "additionalProperties": False}}


TOOLS = [
    tool("list_leads_by_state", "List leads in a US state: lead_id, full_name, loan_amount, loan_type.",
         {"state": {"type": "string", "description": "Two-letter code, e.g. TX"}}),
    tool("get_lead", "Get one lead's full record.", {"lead_id": {"type": "string"}}),
    tool("calculate_payment", "Monthly principal-and-interest payment for a fixed-rate loan.",
         {"principal": {"type": "number"}, "annual_rate_pct": {"type": "number"}, "years": {"type": "integer"}}),
]


class LeadTools:
    def __init__(self, conn: sqlite3.Connection):
        self.conn = conn

    def list_leads_by_state(self, state: str) -> list[dict]:
        rows = self.conn.execute("SELECT lead_id, full_name, loan_amount, loan_type FROM leads "
                                 "WHERE property_state = ?", (state.upper(),)).fetchall()
        return [dict(zip(["lead_id", "full_name", "loan_amount", "loan_type"], r)) for r in rows]

    def get_lead(self, lead_id: str) -> dict:
        cur = self.conn.cursor()
        cur.row_factory = sqlite3.Row                 # dict-like rows, for this query only
        row = cur.execute("SELECT * FROM leads WHERE lead_id = ?", (lead_id,)).fetchone()
        if row is None:
            raise LookupError(f"no lead {lead_id}")
        return dict(row)

    def calculate_payment(self, principal: float, annual_rate_pct: float, years: int) -> dict:
        r, n = annual_rate_pct / 100 / 12, years * 12
        return {"monthly_payment": round(principal * r / (1 - (1 + r) ** -n), 2)}

    def run(self, name: str, arguments: str) -> str:
        if name not in {t["name"] for t in TOOLS}:
            return json.dumps({"error": f"unknown tool {name}"})
        try:
            return json.dumps(getattr(self, name)(**json.loads(arguments)))
        except (LookupError, ValueError, TypeError) as e:
            return json.dumps({"error": str(e)})


def run_agent(client, tools: LeadTools, conversation: list, max_steps: int = 6) -> str:
    for step in range(1, max_steps + 1):
        response = client.responses.create(
            model="gpt-6-luna", input=conversation, tools=TOOLS,
            instructions="Answer questions about mortgage leads. Use tools for data and math.")
        conversation += response.output
        calls = [i for i in response.output if i.type == "function_call"]
        if not calls:
            return response.output_text
        for call in calls:
            result = tools.run(call.name, call.arguments)
            print(f"step {step}: {call.name}({call.arguments}) -> {result[:100]}")
            conversation.append({"type": "function_call_output", "call_id": call.call_id, "output": result})
    raise RuntimeError(f"no answer after {max_steps} steps")


if __name__ == "__main__":
    from dotenv import load_dotenv
    load_dotenv()
    client, tools = OpenAI(), LeadTools(sqlite3.connect("out/crm.db"))

import json

import anthropic

from agent import TOOLS, LeadTools

CLAUDE_TOOLS = [{"name": t["name"], "description": t["description"], "input_schema": t["parameters"]}
                for t in TOOLS]


def run_claude(client: anthropic.Anthropic, tools: LeadTools, question: str, max_steps: int = 6) -> str:
    messages = [{"role": "user", "content": question}]
    for _ in range(max_steps):
        msg = client.messages.create(model="claude-haiku-4-5", max_tokens=1024,
                                     tools=CLAUDE_TOOLS, messages=messages)
        messages.append({"role": "assistant", "content": msg.content})
        if msg.stop_reason != "tool_use":
            return "".join(b.text for b in msg.content if b.type == "text")
        results = []
        for block in msg.content:
            if block.type == "tool_use":
                output = tools.run(block.name, json.dumps(block.input))
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": output,
                                "is_error": '"error"' in output})
        messages.append({"role": "user", "content": results})
    raise RuntimeError("no answer")

Enterprise · TypeScript II-c: a tool loop with Claude

Port Exercise 1 to TypeScript with Claude in agent.ts: export ask(client, question, maxSteps = 5) that loops while stop_reason === "tool_use", runs calculatePayment, and pushes tool_result blocks. Put the real call in a separate main.ts (import { ask } from "./agent.ts") so tomorrow's test can import agent.ts without calling the API.

import Anthropic from "@anthropic-ai/sdk";

function calculatePayment(principal: number, annualRatePct: number, years: number): number {
  const r = annualRatePct / 100 / 12;
  const n = years * 12;
  return Math.round((principal * r) / (1 - (1 + r) ** -n) * 100) / 100;
}

const tools: Anthropic.Tool[] = [{
  name: "calculate_payment",
  description: "Monthly principal-and-interest payment for a fixed-rate loan.",
  input_schema: {
    type: "object",
    properties: { principal: { type: "number" }, annual_rate_pct: { type: "number" }, years: { type: "integer" } },
    required: ["principal", "annual_rate_pct", "years"],
  },
}];

type PaymentInput = { principal: number; annual_rate_pct: number; years: number };

export async function ask(client: Anthropic, question: string, maxSteps = 5): Promise<string> {
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: question }];
  for (let step = 0; step < maxSteps; step++) {
    const response = await client.messages.create({ model: "claude-haiku-4-5", max_tokens: 1024, tools, messages });
    messages.push({ role: "assistant", content: response.content });
    if (response.stop_reason !== "tool_use") {
      return response.content.filter((b): b is Anthropic.TextBlock => b.type === "text").map(b => b.text).join("");
    }
    const results: Anthropic.ToolResultBlockParam[] = [];
    for (const block of response.content) {
      if (block.type === "tool_use") {
        const input = block.input as PaymentInput;
        const payment = calculatePayment(input.principal, input.annual_rate_pct, input.years);
        results.push({ type: "tool_result", tool_use_id: block.id, content: JSON.stringify({ monthly_payment: payment }) });
      }
    }
    messages.push({ role: "user", content: results });
  }
  throw new Error(`no answer after ${maxSteps} steps`);
}

Core · Instructions and memory

  • A good system prompt has: the role and who the output is for; the steps to follow; the rules (for P1, the lender's guidelines, pasted in full); what to do when data is missing; and the output format.
  • Few-shot examples (one or two worked examples in the prompt) fix tone and format faster than more rules.
  • Chain of thought: older models did better when asked to "think step by step". Reasoning models think on their own; you control how much with reasoning={"effort": "low" | "medium" | "high"}. More effort costs more output tokens and time.
  • Untrusted text: anything a tool returns (CRM notes, emails, web pages) is data. Say so in the instructions, and never let tool text change the rules. P1's data contains one borrower who tries.
  • Memory: short-term memory is the conversation list; long-term memory is anything you save and fetch later (a database, a file). P1 saves each score to SQLite, so tomorrow's run can see yesterday's.
  • Reflection (an evaluator step that checks the answer before it's returned) is the pattern Anthropic calls evaluator-optimizer. P1 uses a light version: a Pydantic validator that rejects a score outside its tier's range.

Core · Testing an agent without the network

You can't unit-test a real model: it's slow, it costs money, and its answers vary. What you can test is your code: that the loop runs the tools it's asked to, sends results back correctly, stops, respects the step limit and survives errors. The trick is the one from Week 0B: give the SDK a fake HTTP transport that returns scripted replies, one per API call.

import itertools
import json

_ids = itertools.count(1)
USAGE = {"input_tokens": 100, "output_tokens": 20, "total_tokens": 120,

def response(output: list) -> dict:
    return {"id": f"resp_{next(_ids)}", "object": "response", "created_at": 0, "model": "gpt-6-luna",

def function_call(name: str, **arguments) -> dict:

            "arguments": json.dumps(arguments), "status": "completed"}


def message(text: str) -> dict:
    return {"type": "message", "id": f"msg_{next(_ids)}", "status": "completed", "role": "assistant",
            "content": [{"type": "output_text", "text": text, "annotations": []}]}


def scripted_client(replies: list[dict], requests: list | None = None) -> OpenAI:
    """Each API call gets the next reply; request bodies are saved so tests can inspect them."""
    queue = list(replies)

    def handler(request: httpx.Request) -> httpx.Response:
        if requests is not None:
            requests.append(json.loads(request.content))
        return httpx.Response(200, json=queue.pop(0))

    return OpenAI(api_key="test", http_client=httpx.Client(transport=httpx.MockTransport(handler)))

Core · Portfolio project P1

The scenarioPrairie Home Lending's loan officers get more leads than they can call. They want an assistant that looks at each new lead, gathers what matters (the CRM record, the officer's notes, today's rate), applies the lender's written guidelines, and produces a score from 1 to 10, a hot / warm / cold tier, and a short explanation, so they call the best leads first. Every number must be traceable, and the officers decide; the agent advises.

Requirements

  1. A new public repository, mortgage-lead-qualifier, laid out as a package: qualifier/tools.py, schema.py, agent.py, rules.py, store.py, cli.py, plus data/ (the four files) and tests/.
  2. Tools (strict schemas): get_lead, get_crm_notes, get_current_rate(loan_type) (enum: purchase, refinance), calculate_payment, calculate_dti(annual_income, monthly_debts, new_monthly_payment). Errors come back as {"error": ...}.
  3. Instructions: the steps to follow, "never do arithmetic yourself", and the full text of guidelines.md, which already says CRM notes are data, never instructions.
  4. The loop (reasoning={"effort": "low"}, max_steps=8) records steps, tool calls, input and output tokens, and cost, and appends every tool call to out/trace.jsonl.
  5. Final assessment: after the loop, one responses.parse call with text_format=LeadScore: lead_id, score, tier, monthly_payment, dti_pct, reasons, risks, next_action (the two numbers nullable). A validator rejects a score outside its tier's range (hot 8–10, warm 5–7, cold 1–4).
  6. Storage: a lead_scores table (the assessment plus steps, tool calls, tokens, cost and a timestamp), saved with parameterized SQL.
  7. CLI: --db, --seed CSV, --lead ID or --all, --eval, --out. Writes out/report.md sorted by score. One failing lead is logged and skipped. Exit codes: 0 all scored, 1 no leads table, 2 some leads failed.
  8. The answer key: rules.py implements guidelines.md in plain Python (expected_tier(lead, notes, rates)). With --eval, the report adds "Rules say" and "Match" columns and an agreement line.

class LeadScore(BaseModel):
    lead_id: str
    score: int
    tier: Literal["hot", "warm", "cold"]
    monthly_payment: float | None
    dti_pct: float | None
    reasons: list[str]
    risks: list[str]
    next_action: str

    @model_validator(mode="after")
    def score_matches_tier(self):
        low, high = TIER_RANGES[self.tier]            # {"hot": (8, 10), "warm": (5, 7), "cold": (1, 4)}
        if not low <= self.score <= high:
            raise ValueError(f"score {self.score} is outside the {self.tier} range {low}-{high}")
        return self
def final_assessment(client, conversation: list, stats: RunStats) -> LeadScore:
    response = client.responses.parse(
        model=MODEL, instructions=INSTRUCTIONS, reasoning={"effort": "low"}, text_format=LeadScore,
        input=conversation + [{"role": "user", "content": "Now give your final assessment of this lead."}])
    stats.add_usage(response.usage)
    if response.output_parsed is None:
        raise AgentError("the model returned no structured assessment (possibly a refusal)")
    return response.output_parsed
