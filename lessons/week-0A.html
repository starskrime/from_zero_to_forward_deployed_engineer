3. Virtual environments: one isolated toolbox per project

The problem: if every package goes into one shared Python, projects start to conflict. One project needs one version of a library, another needs a different one, and nobody else can reproduce your setup.

The fix: each project gets its own .venv folder with its own Python and packages. "Activating" it tells your terminal to use that folder's python and pip.

$ python3 -m venv .venv            # create: once per project
$ source .venv/bin/activate        # activate: every new terminal (Windows: .venv\Scripts\activate)
(.venv) $ which python                # proof: points inside .venv
(.venv) $ pip install rich
(.venv) $ pip freeze > requirements.txt  # record exact versions
(.venv) $ deactivate

To rebuild the environment elsewhere: create and activate a new .venv, then pip install -r requirements.txt.

4. VS Code, set up properly

  1. Install the Python extension from Microsoft.
  2. Enable the code command: ⌘⇧P → "Shell Command: Install 'code' command in PATH". Now code . opens the current folder.
  3. ⌘⇧P → "Python: Select Interpreter" → choose the one inside .venv.
  4. Open the built-in terminal with ⌃`. It activates the selected environment automatically.

Core · Packages and git

1. Module, package, import

  • A module is one .py file. text.py is the module text.
  • A package is a folder of modules with an __init__.py (it can be empty).
  • Imports follow folders with dots: from greeter.text import shout means "open greeter/text.py and take shout".
import csv                          # whole module; use as csv.DictReader
from pathlib import Path            # one name from a module
from greeter.text import shout      # your own package, same syntax

2. __name__ and if __name__ == "__main__":

Python sets __name__ in every file. If you run the file, it's "__main__"; if another file imports it, it's the module's name (like "greeter.text"). The if check lets one file be both a reusable library and a runnable script.

def shout(name: str) -> str:
    return f"HELLO, {name.upper()}!"

if __name__ == "__main__":
    print(shout("test"))   # runs with: python -m greeter.text, NOT when imported

3. __main__.py and python -m

Put a __main__.py inside a package, and python -m greeter runs it. Always run from the project root, the folder that contains the package.

4. The project layout you'll use all program

lead-intake/                 ← project root: run commands from here
├── .venv/                   ← ignored by git

Keeping input/output, business rules and the command line separate is exactly the habit hiring managers look for, and it's what makes code testable (next week).

Three data-wrangling functions

~45 min

In code/week-0A/drills/tue_drills.py, write and test these (you'll use all three patterns this weekend):

  1. unique_emails(emails): remove duplicates ignoring case and surrounding spaces, keep first-seen order, return lowercase.
  2. leads_per_state(states): count per state (uppercased), return a list of (state, count), most common first, ties alphabetical.
  3. ids_by_loan_type(rows): given dicts with lead_id and loan_type, return {loan_type: [ids…]}.
assert unique_emails(["A@x.com", "b@x.com", " a@X.com "]) == ["a@x.com", "b@x.com"]
assert leads_per_state(["TX", "ca", "TX", "CA", "ny"]) == [("CA", 2), ("TX", 2), ("NY", 1)]
A set answers "have I seen this?" quickly. collections.Counter counts. dict.setdefault(key, []) creates a list the first time a key appears. Sort with a key of (-count, name).
from collections import Counter


def unique_emails(emails: list[str]) -> list[str]:
    seen, out = set(), []
    for e in emails:
        key = e.strip().lower()
        if key not in seen:
            seen.add(key)
            out.append(key)
    return out


def leads_per_state(states: list[str]) -> list[tuple[str, int]]:
    counts = Counter(s.strip().upper() for s in states)
    return sorted(counts.items(), key=lambda kv: (-kv[1], kv[0]))


def ids_by_loan_type(rows: list[dict]) -> dict[str, list[str]]:
    groups: dict[str, list[str]] = {}
    for r in rows:
        groups.setdefault(r["loan_type"], []).append(r["lead_id"])
    return groups

Core · Files and bad data

1. Paths with pathlib

from pathlib import Path

HERE = Path(__file__).parent                 # the folder this .py file lives in
INPUT = HERE / "data" / "leads_sample.csv"    # "/" joins path parts
OUT_DIR = Path("out")
OUT_DIR.mkdir(parents=True, exist_ok=True)   # create if missing; no error if it exists

2. Reading CSV: every value is a string

import csv

with INPUT.open(newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):     # each row is a dict keyed by the header
        print(row["credit_score"])    # '742'  ← a str, not an int!
  • Every value is text. An empty cell is "", not None.
  • newline="" is required by the csv docs; encoding="utf-8" handles names like "Müller".
  • Number rows the way a person sees the file: the header is line 1, so use enumerate(reader, start=2).

3. Converting text safely

int("742")                        # 742
int("")                           # ValueError
int("7.5")                        # ValueError: use float()
float("three")                    # ValueError
from datetime import date
date.fromisoformat("2026-09-31")  # ValueError: September has 30 days

A value can convert fine and still be wrong, like a credit score of 905. That's a range check, and you write it yourself.

4. Exceptions: catch, record, continue

def parse_credit_score(raw: str) -> int:
    if raw.strip() == "":
        raise ValueError("credit_score is missing")
    score = int(raw)
    if not 300 <= score <= 850:
        raise ValueError(f"credit_score {score} is outside 300-850")
    return score

try:
    score = parse_credit_score(row["credit_score"])
except ValueError as e:              # catch the SPECIFIC error, never a bare except:
    errors.append(str(e))            # record it, and the loop continues
The data-pipeline mindsetOne bad row must never crash the run. Validate each row, collect errors with enough context to fix them (row, ID, field, reason), and keep going. Stop only when the whole run is meaningless, like a missing input file. The same pattern returns when agent tools fail.

5. Writing JSON

import json
with (OUT_DIR / "summary.json").open("w", encoding="utf-8") as f:
    json.dump(summary, f, indent=2)

JSON stores dicts, lists, strings, numbers, booleans and null, but not date objects or sets. Convert with d.isoformat() and sorted(s).

import csv
import json
from pathlib import Path

HERE = Path(__file__).parent
INPUT = HERE / "data" / "leads_sample.csv"
OUTPUT = HERE / "out" / "summary.json"


def parse_credit_score(raw: str) -> int:
    if raw.strip() == "":
        raise ValueError("credit_score is missing")
    score = int(raw)
    if not 300 <= score <= 850:
        raise ValueError(f"credit_score {score} is outside 300-850")
    return score


def main() -> None:
    total, scores, errors = 0, [], []
    with INPUT.open(newline="", encoding="utf-8") as f:
        for row_number, row in enumerate(csv.DictReader(f), start=2):
            total += 1
            try:
                scores.append(parse_credit_score(row["credit_score"]))
            except ValueError as e:
                errors.append({"row": row_number, "lead_id": row["lead_id"], "error": str(e)})

    summary = {
        "total_rows": total,
        "valid_scores": len(scores),
        "average_score": round(sum(scores) / len(scores), 1) if scores else None,
        "errors": errors,
    }
    OUTPUT.parent.mkdir(parents=True, exist_ok=True)
    with OUTPUT.open("w", encoding="utf-8") as f:
        json.dump(summary, f, indent=2)
    print(f"Wrote {OUTPUT} ({len(errors)} errors)")


if __name__ == "__main__":
    main()

Clean first (strip, remove $ and commas), then convert. For dates, try one format; if it raises ValueError, try the next with datetime.strptime(raw, "%m/%d/%Y"); if both fail, raise your own clear error.
from datetime import date, datetime


def parse_amount(raw: str) -> float:
    cleaned = raw.strip().replace("$", "").replace(",", "")
    if cleaned == "":
        raise ValueError("amount is missing")
    return float(cleaned)


def parse_date(raw: str) -> str:
    raw = raw.strip()
    try:
        return date.fromisoformat(raw).isoformat()
    except ValueError:
        pass
    try:
        return datetime.strptime(raw, "%m/%d/%Y").date().isoformat()
    except ValueError:
        raise ValueError(f"unrecognized date: {raw!r}") from None

# lead_intake/cli.py
import argparse
import logging
import os
import sys
from pathlib import Path

from dotenv import load_dotenv

logger = logging.getLogger(__name__)


def setup_logging() -> None:
    load_dotenv()
    level = os.getenv("LOG_LEVEL", "INFO").upper()
    logging.basicConfig(level=level, format="%(asctime)s %(levelname)-8s %(name)s: %(message)s")


def parse_args(argv=None) -> argparse.Namespace:
    parser = argparse.ArgumentParser(prog="lead_intake",
                                     description="Validate a CSV of mortgage leads and write a JSON report.")
    parser.add_argument("input", type=Path, help="path to the leads CSV file")
    parser.add_argument("--output-dir", type=Path, default=Path("out"),
                        help="folder for the JSON files (default: out)")
    return parser.parse_args(argv)


def main(argv=None) -> int:
    setup_logging()
    args = parse_args(argv)
    logger.debug("Arguments: %s", args)
    if not args.input.exists():
        logger.error("Input file not found: %s", args.input)
        return 1
    logger.info("Would process %s into %s", args.input, args.output_dir)
    return 0


if __name__ == "__main__":
    sys.exit(main())

Deep practice · Undoing things in git

Everyone makes git mistakes. Learn the safe undo moves now, in a throwaway repo (code/week-0A/git-sandbox/), so they're not scary later.

  1. Commit a file, then fix the commit message with git commit --amend.
  2. Stage a file by accident, then unstage it with git restore --staged file.
  3. Edit a file, then throw the edit away with git restore file. (This one is destructive: know that it is.)
  4. Make a bad commit, then undo it safely with git revert HEAD, which adds a new commit instead of rewriting history.

Core · The project: Lead Intake CLI

The scenarioYou're the engineer at a mortgage lender. Every night the website exports new leads as a CSV. The CRM import rejects the entire file if any row is bad, so sales loses a day of leads to one typo. Build a command-line tool that validates the file, writes clean leads as JSON, and produces a report telling the web team exactly what to fix.

This warm-up isn't one of your 10 portfolio projects, but its clean output is the kind of data your Week 1 lead-qualifier agent will read.

Validation rules

FieldRuleStore as
lead_idNot empty; not a duplicate of an earlier rowstr
full_nameNot empty after trimmingstr (trimmed)
emailContains @, and the part after it contains a .str (lowercase)
loan_amountA number, greater than 0, at most 5,000,000float
credit_scoreA whole number from 300 to 850int
annual_incomeA number, 0 or morefloat
property_stateA 2-letter US state code, or DCstr (uppercase)
loan_typepurchase or refinancestr (lowercase)
created_atA real calendar date, YYYY-MM-DDstr (ISO date)

Check every field and collect all of a row's problems. A row is valid only with zero errors.

Outputs

# out/report.json (shape)
{
  "run_at": "2026-10-03T14:02:11",
  "input_file": "data/leads_sample.csv",
  "total_rows": 20,
  "valid_rows": 0,
  "invalid_rows": 0,
  "errors_by_field": {"email": 0, "loan_amount": 0, "…": 0},
  "errors": [{"row": 4, "lead_id": "L-1003", "field": "email", "message": "…"}]
}

Command: python -m lead_intake data/leads_sample.csv --output-dir out. Exit 0 when the run completes (even with invalid rows), 1 if the input file is missing. One INFO summary line at the end, one DEBUG line per row.

Build order (commit after each step)

  1. io_utils.py: read_rows(path) → list of (row_number, row_dict); write_json(path, data). Wire into cli.py, log the count. Commit.
  2. validation.py: validate_row(row, seen_ids) → (lead_or_None, errors). Start with lead_id and full_name. Commit.
  3. Add loan_amount, credit_score, annual_income (reuse your Wednesday drills). Commit.
  4. Add email, property_state, loan_type, created_at. Commit.
  5. Build report.json with errors_by_field (your Tuesday counting drill). Commit and push.
Hints

validate_row(): stuck?

This is your project, so there's no full solution. Hints go up to a snippet. For a code review, share your repo with your AI tutor.

One function, one row. Keep an errors list and a lead dict. For each field: convert, range-check, and on failure append {"field", "message"} and move on. Duplicates: the caller passes a set of IDs seen so far; add the ID after checking, so the second occurrence is flagged. Return the lead only if errors is empty.
errors = []; lead = {} → lead_id: strip; empty → error; in seen_ids → "duplicate"; else store; add to seen_ids → numeric fields: try convert → range → except ValueError → error → … → return (lead if not errors else None, errors). A helper like parse_number(raw, field, kind, low, high) removes repetition.
US_STATES = {"AL", "AK", "AZ", …, "WY", "DC"}   # type all 50 + DC; a set gives fast lookup

def validate_row(row: dict, seen_ids: set) -> tuple[dict | None, list[dict]]:
    errors: list[dict] = []
    lead: dict = {}

    raw = row.get("credit_score", "").strip()
    try:
        if raw == "":
            raise ValueError("missing")
        score = int(raw)
        if not 300 <= score <= 850:
            raise ValueError(f"{score} is outside 300-850")
        lead["credit_score"] = score
    except ValueError as e:
        errors.append({"field": "credit_score", "message": str(e)})

    # … the other eight fields …
    return (lead if not errors else None), errors
